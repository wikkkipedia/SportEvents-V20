# ЛР №3 — конструювання підпрограм, SportEvents, варіант 20

Вихідний лістинг 1 (частини 1–4) із методички адаптовано: OrderLine -> RaceChargeLine. Початковий код закомічено до перетворень у bac0999.

## Характеризаційні тести до змін
- Process_RegularClient_Returns1292: 1292.70; новий стан Paid.
- Process_SmallOrder_AddsDelivery: 460; новий стан Shipped.
- Process_CancelledDocument_ReturnsZero: 0; новий стан Cancelled.

Усі три тести спершу виконувалися на вихідному 11-параметровому методі. Після переходу на RaceRequest/RaceOutcome перевіряють ті самі сценарії та підсумки.

## Порівняння
|Показник|До|Після|
|---|---:|---:|
|Параметри головного методу|11|1|
|Непорожні рядки головного методу|84|22|
|Текстова оцінка складності головного методу|31|4|
|Максимальна вкладеність блоків|3|2|
|Тести в усьому рішенні|125 зелених|125 зелених|

Підрахунок скриптом scripts/measure_lab03.py, тобто це **наближена текстова метрика**, а не інструментальний звіт Roslyn.

Валідацію, перевірку рядків, розрахунок сум, знижки, доставку, переходи станів та побудову текстового звіту рознесено в окремі методи. Вхідні 11 параметрів зібрано в один RaceRequest, результат — RaceOutcome. Збережено порядок знижок та округлення.

Команди dotnet build SportEvents.sln -c Release, dotnet test та dotnet format --verify-no-changes пройшли з 0 попереджень та 125/125 зелених тестів.

## Обмеження
Три тести не охоплюють усіх можливих гілок вихідного методу та всього текстового виводу. Для повного доведення еквівалентності потрібно додати більше тестів.
